# 线索评分规则生成器 —— 算法设计与校准方案

> 目标：给定"我想要的客户"的行为样板 → 自动生成评分体系 → ABC 分层 → 给原始线索打标签，
> 并且有一套机制保证这套东西**跑正、不跑歪**。

## 0. 一句话框架

**样本（好客户 + 对照组）→ 行为特征 → 对比分析生成规则 → 评分卡 → 按分布分层 → 打标 → 回测与反馈校准。**

核心不是"描述好客户长什么样"，而是"好客户在哪些行为上**和普通线索显著不一样**"——
规则生成器的本质是做**对比**，不是做画像。校准靠**排序性回测 + 反馈闭环**，不靠感觉。

## 1. 整体闭环

```
种子样本(成交/高意向客户) ┐
                         ├─▶ 行为特征提取 ─▶ 规则生成器(对比分析) ─▶ 评分卡(权重+分箱)
对照组(普通/流失线索)     ┘                                              │
                                                                        ▼
  反馈(成交/打回/漏检) ◀── 销售跟进 ◀── ABC 分层 + 打标签 ◀── 原始线索批量打分
          │                                                             ▲
          └────────────── 每月回流样本，重新校准规则 ────────────────────┘
```

## 2. 第一个关键决策：必须有对照组

这是最容易跑歪的地方。如果只喂"我想要的人"的样本，算法只能学出这群人的**共性**
（比如"都注册过账号"——废话），学不出**区分性**。

所以规则生成器的输入是**两堆人**：

| 组 | 定义 | 数量要求 |
| --- | --- | --- |
| 正样本 | 已成交 / 明确高意向的客户 | ≥ 50~100 个（少于 50 个先别自动化，人工定规则） |
| 对照组 | 从原始线索池随机抽样，或明确流失/无效的线索 | ≥ 正样本的 3~5 倍 |

每个候选特征都要回答同一个问题：**它在正样本里的出现率，比在对照组里高多少倍？**
高得不明显的特征，再符合直觉也不要。

## 3. 特征工程：把行为流水变成可比较的指标

行为原始数据是流水（谁、什么时间、做了什么），规则不能直接长在流水上，
要先聚合成特征。推荐按四个维度建**特征字典**：

- **Recency 近度**：最近一次关键行为距今天数
- **Frequency 频次**：7 / 30 天内的访问次数、互动次数
- **Depth 深度**：看过价格页 / 案例页、停留时长、注册流程完成到第几步
- **Identity 身份**：行业、公司规模、渠道来源（静态属性）

另外把**关键动作（magic moments）**单独列出来：看过价格页、下载过资料、主动发起咨询、
添加过联系方式等——这类动作往往一条顶十条普通特征。

> ⚠️ **时间截断防泄漏**（跑歪重灾区）：每个正样本的特征，只能取"他成为好客户**那一刻之前**"
> 的行为。否则规则学到的是结果不是原因——比如"签过合同"能 100% 区分好客户，但对预测
> 新线索毫无价值。回测时完美、上线后失效，八成是这里漏了。

## 4. 规则生成：用 lift 找区分性特征

对特征字典里的每个特征，先分箱（如访问次数切成 0 / 1-3 / 4-10 / >10），然后逐箱计算：

- `p1` = 正样本命中率，`p0` = 对照组命中率
- **lift = p1 / p0**（区分力：好客户比普通人多几倍地做这件事）
- **覆盖率** = 命中该箱的正样本占比（别选只覆盖 3 个人的"完美特征"）

**入选标准（三条同时满足）：**

1. lift ≥ 2（≥ 3 为强特征）
2. 正样本覆盖率 ≥ 20%
3. 每箱样本量 ≥ 20（防止小样本巧合）

进阶做法（可选，等数据量够了再上）：

- 套用信贷评分卡的 **WOE/IV**：`WOE = ln(该箱正样本占比 / 该箱负样本占比)`，
  IV 衡量特征整体区分力，IV > 0.1 才保留。这是银行风控几十年的标准做法，天然可解释。
- 训练一棵**浅决策树（深度 ≤ 3）**或逻辑回归，把分裂路径 / 系数翻译回规则。
  依然可解释，且能发现特征组合（如"看过价格页 **且** 7 天内回访 ≥ 2 次"）。

**规则条数控制在 5~10 条**，每条必须能用一句业务话讲清楚为什么合理；
讲不清楚的删掉。规则越多越像是在背诵那几十个样本（过拟合），而不是在学规律。

> 关于用 LLM：LLM 适合做特征字典的头脑风暴（"这类客户还可能有哪些行为信号？"）和把
> 规则翻译成业务语言；**不适合让它看几个样本直接拍权重**——权重必须来自数据对比，
> 否则整个体系建立在模型的想象上，无从校准。

## 5. 评分体系：分箱赋分 + 加权求和

- 每条入选规则按 lift（或 WOE）大小赋分：lift 5x → 30 分，3x → 20 分，2x → 10 分（量级示意，按实际分布定）。
- 线索总分 = 命中规则的分数之和。
- **分层不要拍脑袋定阈值**：把全量原始线索打完分，看分数分布再切——
  - 按分位数切：如 top 10% = A，接下来 20% = B，其余 = C；
  - 或按预期转化率切：回看每个分数段的历史转化率，"预测转化率 ≥ 3× 平均"的段位定为 A。
- A 层的大小要匹配销售产能：A 层是"优先打"的名单，切出 5000 个 A 但销售一天只能跟 50 个，分层就失去意义。

## 6. 怎么算"跑正了"：校准与验收标准

核心检验只有一条：**排序性**——A 层的实际转化率 > B 层 > C 层，单调递减，
且 A 层显著高于全量平均（**lift@A ≥ 3 算好，≥ 2 及格，< 1.5 说明规则没用**）。

具体四步：

1. **留出回测**：生成规则只用 70% 的样本，剩 30% 锁起来不参与；规则定稿后给这 30% 打分，
   看排序是否依然成立。再做一次历史回测：拿 3 个月前的线索、按**当时**的行为数据打分，
   看后来实际成交的人是不是集中在 A 层。
2. **灰度上线，隔离自证效应**：先只把 A 层名单的一半给销售，另一半照旧流程，对比转化率。
   这一步排除"因为标了 A 所以销售更用力跟，所以转化高"的自我实现——不做这步，
   你永远分不清是规则准还是销售偏心。
3. **三个常驻监控仪表**：
   - **Lift@A**（效果）：A 层转化率 / 整体转化率，跌破 2 要查；
   - **分层占比**（分布）：A 层占比是否稳定在设计值附近，突然膨胀或萎缩说明打分口径变了；
   - **PSI 稳定性**（漂移）：各特征在新线索里的分布 vs 建模时的分布，PSI > 0.25 报警，
     说明人群变了，规则需要重新生成。
4. **反馈闭环**：销售把 A 级打回（"这人不行"）→ 记为负反馈样本；
   没标 A 却成交了 → 记为漏检样本。**每月**把这两堆喂回规则生成器重新跑一遍第 4 节，
   规则的增删和权重调整都由数据驱动，不手动拍。

## 7. 常见跑歪方式 checklist

- [ ] 只有正样本没有对照组 → 学出的是共性不是区分性特征
- [ ] 特征用了未来信息（数据泄漏）→ 回测完美、上线失效
- [ ] 阈值拍脑袋 → A 层要么太少没得跟，要么太多等于没分层
- [ ] 规则太多太细 → 过拟合样本里那几十个人
- [ ] 不做灰度对照 → 分不清规则准还是销售自证
- [ ] 上线后不回收反馈 → 行为漂移后规则腐化还在照旧打分
- [ ] 正样本 < 50 就急着自动生成 → 先人工定规则攒数据，数据够了再自动化

## 8. 落地路线

- **MVP（1~2 周）**：人工整理特征字典 → 写 lift 对比脚本（一个 Python 脚本 + 两张表就够）→
  评分卡 v1 → 历史数据回测验证排序性。
- **V1**：接入线索池批量打分打标 → 灰度上线 A 层名单 → 搭三个监控仪表。
- **V2**：反馈样本自动回流 → 每月自动重跑规则生成与校准 → （可选）升级为逻辑回归/树模型，
  但保持"规则可解释"这条红线不破。
