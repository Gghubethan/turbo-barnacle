# ④ 精准修改 · 零编造契约

**这一阶段只动用户点名要改的条目。** 每改一条，都要能指着原文说"这句话里的每个事实都来自这里"。

## 允许 / 禁止

| ✅ 允许 | ❌ 禁止 |
| --- | --- |
| 换措辞、换句式、换动词 | 新增公司、职位、项目、时间、学历、证书 |
| 调整语序，把结果提前 | 新增任何原文没有的数字、百分比、规模、金额 |
| 把散落在多处的**原文事实**合并成一条 | 把"参与"升级成"主导"、"协助"升级成"负责" |
| 补充**原文已有**的上下文（如别处提到的团队规模） | 把模糊表述具体化（"提升效率"→"提升 30%"） |
| 删除冗余、拆长句 | 删除会改变事实含义的限定词（"试点""部分""协助"） |
| 用 JD 的说法替换同义表述 | 加入用户没做过的技能关键词 |

**职级词是事实，不是修辞。** "参与"改"主导"是编造，不是优化——这是面试当场穿帮的重灾区。

## 缺数据 → 占位符

原文没有的数据，一律写：

```
【待补充：这个看板覆盖多少个指标】
```

占位符要求：

1. **写清楚要补什么**，不要只写 `【待补充】`——用户看不懂就填不出来。
2. 一条 bullet 里占位符不超过 2 个，否则这条实际上是让用户重写。
3. 交付前占位符必须清零（`09-final-qa.md` 会卡这一关）。
4. 用户说"我也没有数据" → 就用**非数字的结果**：上线状态、被采用、沿用至今、覆盖范围、复用次数。永远有比编数字更好的选择。

## 改写公式

```
[强动词] + [做了什么] + [用什么方法/在什么约束下] + [产生了什么结果]
```

例（原文只提到"负责数据看板"和"给增长团队用"，没有数字）：

- 原文：负责用户增长相关的数据分析工作。
- 改后：搭建用户增长数据看板，将分散在【待补充：几个】个数据源的指标统一口径，供增长团队周会决策使用。

注意改后句里"分散数据源""统一口径""周会决策"必须是原文别处出现过的事实；如果原文没有，就不能写，只能保留更简单的版本。

## 中文强动词表（按场景）

- **从无到有**：搭建、建立、设计、落地、上线、从 0 到 1 完成
- **优化改进**：重构、收敛、简化、提速、降低、压缩、自动化
- **推动协作**：主导、牵头、推动、对齐、拉通（慎用黑话）、协调
- **分析研究**：拆解、定位、量化、复盘、验证、归因
- **沉淀复用**：沉淀、标准化、模板化、复用、迁移

英文简历用：Built, Led, Designed, Shipped, Reduced, Increased, Automated, Migrated, Owned, Drove。避免 Responsible for / Helped with。

## 长度与节奏

- 单条 bullet 25-45 字（中文），排版后不超过 2 行。
- 同一段内 bullet 按重要性降序，不按时间。
- 同一段内避免连续三条同一个开头动词。

## 逐条交付格式

改写结果要**对照给**，不要只丢新版本：

```
【第 2 条】
改前：负责用户增长相关的数据分析工作。
改后：搭建用户增长数据看板，统一【待补充：几个】个数据源的指标口径，供增长团队周会决策使用。
依据：动作"搭建看板"来自原文第 12 行；"增长团队使用"来自原文第 14 行；数据源数量原文未提及，留占位。
```

`依据` 这一行是零编造的自证——每条改写都要写，写不出来说明你编了。
