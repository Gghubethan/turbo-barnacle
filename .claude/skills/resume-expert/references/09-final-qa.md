# ⑨ 终检与交付

交付前逐项过，任何一项没过就不交付。

## 硬性检查

- [ ] **占位符清零**：全文搜 `【待补充` 结果为 0。还有剩的就回去问用户，不要自己填。
- [ ] **事实回溯**：随机抽 3 条改写过的内容，逐句回到 `resume.raw.txt` 找出处。找不到 = 编造，立刻改回。
- [ ] **职级/参与度未被抬高**：对比 `diff.md`，确认"参与"没变"主导"、"协助"没变"负责"。
- [ ] **只改了确认过的条目**：`diff.md` 里出现的 `id` 应当是用户点名的那批。多出来的要么撤回，要么明确告知用户。
- [ ] **联系方式正确**：电话位数、邮箱拼写、链接可访问。**这是最贵的错别字。**
- [ ] **错别字与标点**：中英文标点不混用，全半角一致。
- [ ] **时间线**：倒序、无重叠、空档已有说法。
- [ ] **页数与分页**：符合 `06-layout-review.md`；无经历跨页切断。
- [ ] **ATS 复扫**：对最终产物跑 `ats_check.py`，致命项为 0。
- [ ] **文件名**：`姓名-目标岗位-简历.docx/pdf`。
- [ ] **隐私**：按投递地区确认身份证号/照片/婚育等字段的取舍（见 `02-audit.md` J）。
- [ ] **PDF 可选中文本**：打开 PDF 试着选中一段字。

## 生成对比报告

```bash
python3 .claude/skills/resume-expert/scripts/diff_report.py \
  resume-work/resume.json resume-work/resume.edited.json -o resume-work/diff.md
```

按 `id` 对应，输出改前/改后逐条对照，并统计改动条数。用户需要看到"你到底动了哪些地方"——这比交一份新简历更让人放心。

## 交付说明模板

```
交付：
- 张三-数据分析-简历.docx（可继续编辑）
- 张三-数据分析-简历.pdf（投递用，文字可选中）
- diff.md（修改前后逐条对比，共改动 7 条）

这次改了什么：
1. 工作经历 3 条职责句改成成果句（你补的两个数据已填入）
2. 项目经历整体前移到工作经历之后（原来在最末）
3. 全篇日期格式统一为 2021.03 - 2023.06
4. 排版：字体统一雅黑+Calibri、行距 1.15、页边距 1.8cm、修掉了两处经历跨页

没动的地方及原因：
1. 教育背景表述 —— 已经清晰，改了没有收益
2. 自我评价保留 —— 你说过这段是按目标公司文化写的，属于个人判断

还需要你自己确认：
- 第 2 段经历的"XX 项目"是否可以对外披露（涉及前公司业务）
```

- 原始版本留一份，别覆盖掉。
