# ② 简历诊断 · 规则库

这一阶段**只找问题、只记录，不改字**。逐条扫下面 10 个维度，命中就记一条，附上 `id`（定位用）、原文、命中的规则、默认结论。分级和排序交给 `03-priority.md`。

诊断顺序建议：先 A/B/C（内容层，价值最大），再 D/E（表达层），最后 F/G/H/I/J（形式层）。

---

## A. 成果导向（最高频问题，通常贡献一半的 🔴）

| 信号 | 判定 | 说明 |
| --- | --- | --- |
| 以"负责/参与/协助/配合/进行"开头且**全句无结果** | 🔴 必改 | 纯职责描述。HR 读完不知道你做到什么程度 |
| 有动作有方法，但**结果缺失** | 🟡 值得改 | 补一句结果即可，需要用户提供真实数据 |
| 动作 + 方法 + 结果齐全 | ⚪ 不动 | 已达标，不要为了改而改 |
| 通篇"熟悉/了解/掌握"堆技能却无使用场景 | 🟡 | 技能要绑事实，否则等于没写 |

判定口诀：**一条 bullet 读完，能不能回答"所以呢？"** 回答不了就是职责句。

## B. 量化

- 完全无数字的经历段 → 🔴（整段级问题，不是单条）。
- 有数字但**无基线**（"提升了 30%" 但不知道从多少到多少）→ 🟡。
- 数字与职级/时长明显不匹配（实习 3 个月"主导千万级项目"）→ 🔴，**且必须直说可信度风险**，这是面试当场被拆穿的类型。
- **重要**：识别出"缺量化"只能提示用户补，`04-rewrite.md` 的零编造契约不允许你造数字。

## C. 岗位相关性（有目标岗位时才判）

- 与目标岗位无关的经历占据前排/大篇幅 → 🟡（建议压缩或后移，不是删除）。
- 核心竞争力藏在第 3 段第 5 条 → 🔴（位置问题，改动成本极低、收益极高）。
- 跨行业转岗但完全没有可迁移能力的表述 → 🟡，配合 `05-jd-match.md`。

## D. 语言表达

| 信号 | 判定 |
| --- | --- |
| 形容词堆砌："优秀的""出色地""极强的" | 🟡 删掉，形容词不产生可信度 |
| 第一人称"我"、口语化、感叹号 | 🟡 简历用无主语陈述句 |
| 被动句"被安排""被要求" | 🟡 换主动动词 |
| 长句超过 2 行放不下一个意思 | 🟡 拆句 |
| 中英混杂不一致（一处 "AB test" 一处 "A/B 测试"） | 🟡 统一术语表 |
| 缩写首次出现未展开（"负责 DAU 与 GMV 双提升"） | ⚪ 行业通用词不用展开；小众缩写 🟡 |

## E. 动词质量

- 弱动词：负责、参与、协助、进行、做、处理、推进（无结果时）。
- 强动词（中文）：搭建、主导、重构、拆解、落地、量化、沉淀、收敛、复用、推动上线、从 0 到 1 建立。
- 同一段里同一个动词出现 ≥3 次 → 🟡 换词。

## F. 结构与顺序

- 模块顺序不符合身份（应届把工作经历放教育前 / 社招把教育放最前）→ 🟡，详见 `06-layout-review.md`。
- 经历非时间倒序 → 🔴（HR 阅读习惯，改动成本为零）。
- 单段经历 bullet ≥ 6 条 → 🟡（信息过载，最相关的 3-4 条留下）。
- 单段经历只有 1 条 → 🟡（要么这段不重要该压缩，要么写得太少）。

## G. 信息密度与长度

- 单条 bullet 超过 2 行 → 🟡。
- 单条 bullet 少于 15 个字 → 🟡（信息量不足）。
- 全篇 < 1 页且经历 ≥ 3 年 → 🟡（写得太少，浪费空间）。
- 全篇 > 2 页（应届 > 1 页）→ 🔴，详见 `06-layout-review.md`。
- "自我评价"整段全是形容词 → 🟡 建议删掉或改成"求职意向 + 一句能力锚点"。

## H. 一致性

日期格式（`2021.03` / `2021年3月` / `03/2021` 混用）、公司全称简称混用、标点全半角混用、中英文之间空格、职位名大小写。**这类问题单条价值低，合并成一条"全局一致性"报给用户**，不要每处占一行淹没重点。

## I. 事实与可信度

- 时间空档 > 6 个月且无说明 → 🟡（提示准备说法，不是让他编）。
- 同期两段全职经历重叠 → 🔴 需澄清（可能是兼职/实习没标注）。
- 职级与产出不匹配（见 B）。
- 教育/证书表述模糊（"XX大学相关课程"）→ 🟡 澄清。

## J. 隐私、合规与 ATS 前置

- **中国大陆投递**：身份证号、婚育状况、政治面貌（非体制内岗位）、家庭住址 → 🟡 建议删（无用且泄露隐私）；照片视行业，多数互联网岗 ⚪ 可有可无、外企 🟡 建议删。
- **海外投递**：照片、年龄、性别、婚育、国籍 → 🔴 必删（部分国家属反歧视合规问题）。
- 期望薪资写在简历里 → 🟡 通常不写。
- ATS 相关的形式问题（双栏、文本框、页眉里的联系方式、图表）→ 交给 `07-ats-check.md` 统一出，**不要在这里重复报**。

## 记录格式（内部草稿，不直接给用户）

每条记一行，便于下一步排序：

```
id=exp-1-b2 | 维度=A | 默认=🔴 | 一句话=写的是职责不是成果 | 原文="负责用户增长相关的数据分析工作。"
```

## 诊断阶段的自我约束

- 不写"建议改成……"的完整成品句（那是阶段 ④）；这一步最多给方向。
- 不重复报同一个问题：同一条 bullet 命中 A 和 D，合并成一条，主问题写 A。
- 报够就停：单份简历超过 25 条内部记录时，说明你在挑毛病而不是在做判断——回头合并同类项。
